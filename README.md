# Budget — Telegram Mini App + веб-версия

Актуальная версия опубликована в `budget-staging` и перенесена в `main`. Основной интерфейс тёмный, React + Vite; Worker обслуживает интерфейс, D1 API, Telegram-бота и расписание. Платных AI API нет.

## Что работает в коде
- Операции, доходы и корпоративные обеды; добавление, изменение, удаление и отмена последней записи.
- Быстрый ввод с подтверждением: `кофе 180 Сбер сбп`. Явный способ оплаты: карта, СБП, наличные, банковский перевод.
- Общая серверная база Mini App и браузера, CAS-ревизии против перезаписи параллельных изменений.
- Telegram HMAC авторизация разрешённых пользователей; веб-вход одноразовым кодом `/web` (5 минут), HttpOnly Secure cookie (7 дней), выход.
- Счета, сверка с журналом корректировок, переводы между своими счетами одной валюты и комиссии.
- Цели со связанными накопительными счетами: пополнение является переводом, прогресс берётся из остатка.
- Рассрочки с точным распределением копеек, последним днём короткого месяца и остатком каждого взноса по фактическим оплатам. Списание только после подтверждения платежа.
- Постоянные платежи: создание, пауза, подтверждение; отмена транзакции возвращает неоплаченный статус.
- Долги и возвраты связаны с операциями счетов; правка, удаление и отмена отражаются в остатке долга.
- Обеды: лимит, отгулы, доля рабочего дня, фактические расходы, без начисления будущих дней. Встроен федеральный производственный календарь 2026 года; другие годы помечены предварительными во всех интерфейсах.
- Свои категории, поиск истории, 7-дневные графики и месячные суммы.
- Прогноз на 30 дней по записанным расходам, с указанной полнотой истории и допущениями.
- Настраиваемые минуты и часовой пояс, вопросы об обедах и расходах, ежедневный/воскресный/месячный отчёты. Пропущенные слоты догоняются в пределах 15 минут текущего дня. Работают после настройки Worker cron и бота.
- CSV и JSON с предварительной проверкой, дублями/externalId, выбором изменения остатков или только истории; полный экспорт и восстановление.
- До 50 предыдущих полных состояний каждого профиля в D1 для всех способов финансовой записи: миниаппа, бот и API. Это вспомогательный откат, не замена независимому экспорту. API-добавления транзакций и сохранения миниаппы защищены ключами повторного запроса.
- Для будущего прямого подключения ассистента оставлен защищённый API. ChatGPT в этой сессии к нему не подключён.

## Миграция

Сначала экспортировать актуальные данные из действующего Budget. Имеющийся бэкап проверен отдельно; персональные данные не включены в исходники, сборку или демо.

```sh
node scripts/migrate-backup.mjs ORIGINAL.json NEW.json
```

Скрипт сохраняет новый файл без перезаписи существующего. Проверяет точное сохранение операций, счетов и остатков, пользовательских категорий, долгов, целей, переводов, расписаний, журнала и обеденных настроек. Старый PIN-хэш исключается из нового серверного бэкапа: новый вход основан на Telegram. Исходный файл не меняется.

Импортировать результат через Настройки → Перенести старые данные. Перед заменой экспортировать текущую базу. В D1 предыдущее состояние сохраняется атомарно с заменой. Проверить количество операций, названия категорий и все остатки. Старые операции без счёта остаются без счёта. Не пытаться восстановить исходные остатки из неполной истории.

CSV-шаблон:

```csv
date;amount;note;type;paymentMethod;externalId
2026-10-13;-180;Кофе;expense;sbp;bank-001
2026-10-13;25000;Аванс;income;bank;bank-002
```

Положительная сумма требует явного type. Форматы: UTF-8, разделитель `;`, `,` или табуляция, даты ISO, суммы с точкой/запятой. Это нормализованный формат, не универсальный разбор банковских файлов. Одинаковые дата/сумма/тип/счёт/заметка считаются возможным дублем и пропускаются; для двух одинаковых покупок уточните заметку. Скриншот можно разобрать в чате и импортировать проверенный CSV — OCR/AI API в приложение не встроен.

## Cloudflare: тестовое окружение в существующем аккаунте

Сначала отдельный staging Worker и отдельная D1, например `budget-staging`. Существующий production Worker `budget` и его Supabase не менять. Не использовать production webhook для тестового бота.

1. Скопировать `server/wrangler.example.jsonc` в `server/wrangler.jsonc`; указать staging-имя и отдельную D1. Потребуются доступ к существующему Cloudflare-аккаунту и тестовый Telegram-бот.
2. `npx wrangler d1 create budget-staging` — ID в конфиг.
3. `npx wrangler d1 execute budget-staging --remote --file=server/schema.sql --config=server/wrangler.jsonc`.
4. Задать секреты через `wrangler secret put ... --config=server/wrangler.jsonc`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, опциональный случайный `API_TOKEN` для доверенных интеграций. Не помещать секреты в исходники или сообщения.
5. В vars задать числовой `TELEGRAM_OWNER_ID`, HTTPS `MINI_APP_URL` тестового Worker.
6. Собрать `npm run build`, затем `npx wrangler deploy --config=server/wrangler.jsonc` для staging.
7. В BotFather настроить кнопку Mini App, в Bot API `setWebhook` указать `/telegram/webhook` с `secret_token` равным секрету. Отправить боту `/start` вручную.
8. Импортировать бэкап в staging, сверить остатки и проверить сценарии на телефоне и в браузере. `/web` в боте выдаёт одноразовый код для браузера.
9. Проверить запись/редактирование/отмену, СБП, перевод, сверку, повторный импорт, рассрочку, конфликт двух устройств, отчёты и настройки расписания. При отсутствии сети запись должна показать ошибку и не подтверждать сохранение.

После приёмки можно перенести проверенные bindings/сборку в существующий `budget` Worker, предварительно сохранив текущий deployment и свежий JSON. Это отдельный шаг, в текущей работе не выполнен. При откате вернуть прежний deployment и исходное хранилище; новые записи из staging/новой D1 сначала экспортировать и сверить, чтобы не потерять их.

## API

`GET /api/v1/state`; `PUT /api/v1/state` с `{expectedRevision,data}`; `POST /api/v1/transactions` с `Idempotency-Key`; `GET /api/v1/summary?from=...&to=...`.

Авторизация Telegram initData, веб-cookie или Bearer API_TOKEN. Telegram-код действителен 1 час — затем открыть Mini App заново. Сервер защищён от стороннего Telegram ID, поддельных подписей, повторного веб-кода и конфликтов ревизий. Интеграция с ChatGPT потребует отдельного подключения защищённого API/коннектора, оно не создано автоматически.

## Проверки и оставшиеся ограничения

402 автоматических теста покрывают ядро, миграцию, SQL D1 через SQLite, подпись Telegram, веб-сессии, расписание, импорт, сверку и рассрочки. Сборки и тесты прошли в CI на Linux/Windows; Chromium проверил ключевые финансовые сценарии на ширинах 320–1280 px. После staging deployment выполнены проверки хранилища и рендера карточки, по журналу CI патчноут доставлен пяти пользователям без ошибок. Отдельная приёмка на физическом телефоне и в Telegram WebView остаётся необходимой.

Нет автоматического доступа к банкам, офлайн-очереди, оплаты через приложение, автоматического OCR, платного AI, начисления ожидаемой зарплаты или произвольного обмена валют. Валютные курсы перенесены из настроек и не являются актуальной банковской котировкой. Ожидаемые доходы отображаются только в прогнозе и не увеличивают фактический остаток. Календарь учитывает неподтверждённые и просроченные обязательства. Подтверждённый возврат долга связан с операцией счёта. Некоторые инструменты архивного интерфейса остаются отдельными; не все его возможности перенесены.

Отправка отчётов защищена от обычного повторного cron, но не гарантирует exactly-once при падении между отправкой Telegram и записью результата. Перед production нужен наблюдаемый контроль доставки/очередь повторов. Не называть эту сборку полностью проверенным production-релизом.

## Обновление визуальной аналитики

Главная: свободные деньги и распределение резервов, быстрые действия, цветные счета, расходы по дням, лимиты, ближайшие платежи и цели. Аналитика: переключение 7/30 дней, категории, сравнение четырёх месяцев за одинаковое число дней, обязательные/повседневные траты, прогноз до дохода (максимум 30 дней). Графики дней, категорий и месяцев открывают отфильтрованные операции. Для прогноза требуется хотя бы 7 дней с расходами за последние 30; это порог показа, не доказательство полноты истории. Для целей можно указать дату и увидеть приблизительный месячный взнос. Цвета категорий согласованы между графиками.

Проверки аналитики входят в общий набор из 402 тестов. Визуальная и интерактивная проверка выполнена в CI Chromium; сравнения реальных ревизий добавлены в [отчёт аудита](docs/MODERNIZATION-4.2.0.md).

## Плавные анимации

Появление разделов (240 мс), карточек, столбиков и полос прогресса; прорисовка линии прогноза; отклик кнопок; раскрытие и закрытие форм через Web Animations API с обработкой повторного нажатия. Настройка prefers-reduced-motion отключает эффекты. При отсутствии Web Animations API формы раскрываются штатно. Анимации не задерживают сохранение операций. Проверена сборка; плавность на реальном телефоне ещё не проверена.
