# Финансовый QA Бюрджета

**Цель:** сохранить денежный смысл, остатки и связи **во всех оболочках**, а не только обеспечить успешный unit-тест одной функции.

## Определи реальные источники

1. Начни с `AGENTS.md` и актуального кода; используй `docs/ROADMAP-5.0.md`, `docs/STORAGE-EVOLUTION.md`, `docs/GLOBAL-SYSTEM-AUDIT-2026-11-01.md` как карту сценариев и известных исторических рисков, **не** как доказательство их текущего статуса.
2. Проследи изменённый путь через `src/ledger.js`, `src/transaction-roles.js`, `src/planned-model.js`, `src/transfer-actions.js`, `src/debt-state.js`, `src/installment-state.js`, `src/finance-events.js`, `server/financial-command.js`, `server/state-persistence.js` и клиентов — только там, где есть фактическая зависимость.
3. Найди существующие тесты на соответствующий контракт в `tests/` и проверки сценариев в `scripts/`. Не пиши новый параллельный тестовый движок.

## Неизменные свойства, проверяемые по затронутой области

- **План отдельно от факта:** дата будущего дохода или обязательства влияет на прогноз, но не меняет остатки без подтверждённого действия.
- **Деньги точны:** суммы и округления до копейки, историческая валюта и фактическое списание со счёта не должны незаметно пересчитываться по новому курсу.
- **Одна операция — один денежный факт:** ручная связь с планом, долгом или взносом не создаёт вторую проводку; повтор запроса, двойное нажатие и потерянный ответ не дублируют эффект.
- **Составные действия согласованы:** перевод изменяет оба счёта; комиссия и связанные записи имеют допустимые роли; отмена/удаление/undo восстанавливают согласованное состояние.
- **Корпоративный обед не является личным расходом** без явной личной доплаты. `history-only` не меняет остаток.
- **Данные и пользователи изолированы:** несовпадающие ревизии, переключение профиля, параллельные устройства, неверные ID, импорт и откат не подменяют и не теряют финансовые записи.
- **Миграция и восстановление:** никакого переключения хранилища без независимой копии, сверки ID/связей/остатков и проверки отката; старая неполная история не используется для пересоздания текущих остатков.

## Матрица сценариев и проверки

Для изменённого контракта составь минимальную таблицу: **состояние до → действие → ожидаемые счета/факты/связи → результат после**. Включи основной сценарий, частичную оплату (если уместна), повтор, отмену, ошибку/конфликт, старые данные и путь через связанные представления (бот, миниаппа, календарь, история, сводка).

Переиспользуй `npm test` для доменных проверок; `npm run worker:check` для серверной сборки/контрактов; `npm run test:browser`, `npm run test:calendar`, `npm run test:payments`, `npm run test:ondemand`, `npm run test:entry` — по затронутым сценариям. Для релизной приёмки также `npm run build`. Проводить финансовые испытания только на вымышленных или явно разрешённых тестовых данных; никаких записей в production для проверки.

**Отчёт:** инвариант, какие действия/суммы проверены, фактический результат и доказательство (тест, ревизия, скриншот или журнал); отдельно — непроверенное и блокеры. Не называй успешную сборку доказательством денежной корректности. Не изменяй данные или код автоматически, если задача была только аудитом.
