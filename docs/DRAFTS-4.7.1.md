# 4.7.1: черновик при смене пользователя

При новом userId из сервера обновлялся ключ сохранённого черновика, но открытая форма могла остаться в памяти предыдущего профиля. Теперь смена владельца очищает открытую форму, быстрый ввод, сохранённую ссылку на форму и незавершённую попытку записи, возвращает обзор и предлагает только черновик нового владельца.

Реальный Chromium-сценарий заполняет 180 ₽ и комментарий, перезагружает страницу, восстанавливает форму, затем обновляет состояние с другим userId. В новом профиле поля суммы и экран записи отсутствуют. Финансовая запись из черновика не создаётся. Локальный прогон обновлённого сценария прошёл; сценарий profile-change также выполняется в финальном CI.

Локальные unit-проверки: 483/483. Сборка, Worker, оба Chromium-набора и release guard проверяются на финальной ревизии в GitHub. После отключения локальной среды тот же проверенный исходный патч перенесён через GitHub; результатов дополнительных локальных запусков не заявляется.

Также исправлено ожидание адаптивной строки перевода в браузерной проверке. Цель проверки — одна видимая кнопка открытия перевода; она больше не зависит от того, успел ли React заменить мобильную разметку настольной сразу после resize.

Release guard требует новый патчноут при изменении приложения и не допускает переписывание истории заметок. Повтор того же неизменённого приложения разрешается только для непустого набора инфраструктурных изменений; изменение src/server/public/index/package/lock/Vite без новой версии по-прежнему отвергается.

Функции и отдельные этапы хранения описаны в [отчёте 4.7.0](RELIABILITY-4.7.0.md). Первая попытка публикации 4.7.0 была остановлена проверкой до deploy; 4.7.1 включает её функциональность и завершающие исправления.
