## Сохранность и миграция

Все изменения добавляют поля к schemaVersion 2. Старые hour-поля читаются как HH:00 без изменения данных. Отсутствующий пояс — Europe/Moscow. Прежние monthly/once и обычные счета остаются совместимы. При редактировании графика создаётся новая связь плана: старые подтверждения и их даты не переписываются.

Новые таблицы user_feedback и user_notification_outbox создаются через CREATE TABLE IF NOT EXISTS и добавлены в schema.sql. Повторное применение схемы не требуется для staging: Worker создаёт таблицы при первом использовании. Расписание Cloudflare теперь * * * * *. Очистка и рассылка обновлений выполняются ежечасно, не каждую минуту.

Скрытие раздела не отменяет финансовые обязательства. Для остановки графика нужно явно приостановить его. Отключение обедов отключает вопросы; старые записи сохраняются в истории и бэкапах. Компания по умолчанию не приписывается новому пользователю.

## Правила импорта

Стандарт — docs/burget-operations-v1.schema.json; исполняемая проверка — src/json-import.js. Неизвестные поля запрещены. Неясные поля из скриншота могут быть null в черновике, но блокируют импорт до исправления/исключения строки. Даты и курсы не угадываются. Будущие операции не импортируются как банковская история.

Внешний банковский ID сравнивается внутри счёта (для переводов — исходного счёта) и не обходится флажком. Похожая дата/сумма/тип/счёт помечается для проверки; пользователь может подтвердить, что это отдельная покупка. История по умолчанию не меняет сверенные остатки. Одновалютные переводы поддерживаются; валютный перевод требует фактического курса и остаётся запрещён до отдельной реализации.

## Ограничения доставки

Cron использует точную настроенную минуту и scheduledTime, а не округлённый час. Реальное прибытие сообщения может запаздывать из-за Cloudflare/Telegram; гарантировать секунду нельзя. При сбое очередь повторяет доставку. Подтверждение дня отменяет ожидающие вопросы. При редком сбое между успешной отправкой внешним API и записью результата в БД возможен повтор — абсолютная exactly-once доставка через Telegram не гарантируется.

## Проверки

npm test; npm run build; npm run worker:check. Проверяется изоляция двух профилей, JSON/CSV, переводы/комиссия/режим истории, отмена, периоды планов, ожидаемые доходы, минутное расписание, полночь/DST/граница недели и месяца, повтор доставки и приватность обратной связи. Исходный финансовый бэкап отдельно проверяется на неизменность массивов операций и счетов после миграции.
