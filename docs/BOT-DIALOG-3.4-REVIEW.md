# Диалог бота — кандидат 3.4.0.0

Локальная версия на основе 3.3.0.0 (f116700b6dfc31aed29d94dc199454e90aa16e19). Публикация одобрена Андреем 16 октября 2026 года. При подготовке выполнялись только локальные проверки; публикация идёт стандартным staging workflow с серверной проверкой и рассылкой.

## Пользовательский сценарий

- Сумма → компактная проверка. Для новых операций используются общие entryDefaults: только подходящая история, существующие обычные счета, без будущих фактов и импортов без изменения остатков. Когда первый выбор счёта неоднозначен, бот продолжает спрашивать. Выбор и валюту можно изменить до подтверждения.
- В проверке доступны счёт, категория, комментарий и все остальные поля. Расходы компании остаются отдельными от личных счетов.
- Форма, выбор полей, проверка и результат обновляют одну текстовую карточку. Личные ответы не удаляются. Для недоступного сообщения отправляется новая карточка.
- Каждая версия клавиатуры получает поколение. Старые кнопки не подтверждают новые поля. Ответ на старый шаг и подтверждение после изменения профиля с другого устройства требуют актуального ввода/проверки.
- Результат использует реальные факты после записи: остаток счёта, остаток долга, график рассрочки или накопление по цели. Кнопка возврата сохраняет контекст сущности; для истории — фильтры и страницу. Отмена открывает проверку общего undoTransaction, без независимых компенсационных проводок.
- commitBotAction сохраняет historyId результата в существующей атомарной квитанции. Это позволяет отменять именно выполненное действие, а не последнее чужое изменение. Повторное подтверждение не создаёт второй записи.
- Навигация приостанавливает незавершённый ввод. «Продолжить» возвращает поля, «Начать заново» явно закрывает прежнюю форму. TTL существующих telegram_drafts остаётся 30 минут с создания. Приостановленный ввод не перехватывает обычный свободный текст.
- Закрытая или истёкшая карточка предлагает актуальные разделы. Для уже выполненного действия явно сказано, что повторной записи не будет.

## Найденный сопутствующий дефект

fieldsFor(payInstallment) ссылался на несуществующий v и падал до запроса даты оплаты. Ошибочная проверка удалена из построения полей; проверка будущей даты остаётся в applyBotAction и общем ledger. Добавлен сквозной сценарий: выбрать рассрочку → оплатить → увидеть 600 ₽ остатка → вернуться в её карточку.

## Проверка и ограничения

235 тестов проходят. Дополнены существующие сценарии без удаления проверок балансов, антидублей, чужих пользователей, импорта и восстановления. Новые проверки покрывают неизменность message_id, быстрый ввод, исправление комментария, точную отмену, старые кнопки, паузу/возобновление/новую запись, истечение TTL, повторную проверку после изменения профиля, фильтры истории, остаток рассрочки и первый выбор валютного счёта.

Сборки Mini App и Worker, Wrangler dry-run без загрузки — успешны. HTML-сравнение использует тексты и кнопки реального обработчика с подставным Telegram и вымышленным профилем. Это не скриншоты и не проверка в живом Telegram.

Временная недоступность Telegram может потребовать новой карточки; абсолютная доставка и отсутствие любых служебных сообщений не обещаются. Результат отражает состояние на момент повторного чтения после коммита. Если с другого устройства уже изменили связанную операцию, общий журнал запрещает некорректную отмену.
