# Бюрджет 3.3 — локальный кандидат на проверку

Кандидат проверен локально и одобрен Андреем для публикации 16 октября 2026 года.
Основание: версия 3.2.0.0, commit 9dcb9a01df58e10b536f3b0881a2fcbb27a5df87.
Публикация выполняется стандартным staging workflow с проверкой изображения и рассылкой заметок об обновлении.

## Изменения

- Быстрый повтор в форме записи и меню бота. Повтор использует общий repeatEntry, заново считает валютное списание, сохраняется только после подтверждения; сумма и поля доступны для изменения.
- Категории ранжируются по частоте за 90 дней, с большим весом последних 30. Будущие операции, импорт без изменения остатков и связанные выплаты не участвуют. Выбранная категория всегда видна. При отключении запоминания порядок исходный.
- Комментарий доступен сразу. Кнопка записи показывает сумму; категория и счёт рядом. На первом экране два обычных счёта и выбранный; все остальные, включая накопления/наличные/вклады, раскрываются явно. Накопления продолжают использовать реальные счета и общую проводку.
- При редактировании и удалении возврат в исходный раздел. История хранит фильтры, показанное число строк и прокрутку. Незавершённая форма остаётся в памяти открытой миниаппы при переходах по панели; это не сохранение после закрытия или перезагрузки. После успешной записи черновик очищается.
- Поля формы заблокированы во время сохранения.
- Просмотр разделов бота редактирует существующее текстовое сообщение; фото заменяется через editMessageMedia, если исходная карточка тоже фото. Несовместимый тип создаёт новое сообщение. Для недоступных карточек предусмотрен запасной путь. Формы ввода и финансовые подтверждения не превращены в навигационные правки.
- Во время запроса картинки sendChatAction(upload_photo), без отдельного служебного сообщения.
- SettingsPage, LunchPage, PaymentsPage, SavingsPage, FeedbackPanel и ReleaseNotes загружаются при открытии. Первый экран и быстрый ввод остаются доступны в исходном пакете.
- Удалён неиспользуемый повторный dashboard-расчёт из корневого компонента.

## Проверки

231 тест: все прошли. В том числе реальные обработчики MiniApp проверены на возврат из редактирования к поиску и прокрутке без создания второй записи, а также на сохранение черновика при переходах. Проверены замена фото, резервная отправка после отказа, обновление текстовой карточки, исправление суммы быстрого повтора до подтверждения и фильтрация источников частых категорий.

Vite build, локальная сборка Worker и Wrangler dry-run с example-конфигурацией: успешно. Команды реального deploy, GitHub write и рассылки не запускались.

Исходный главный JS: 381,24 КБ (gzip 125,43 КБ). Кандидат: около 285,22 КБ (gzip 92,77 КБ), примерно на 25% меньше. Это размер первого JavaScript, не измерение времени открытия приложения, сетевой задержки или времени ответа Telegram. Общий объём файлов не обязан уменьшаться: часть загрузки перенесена на момент открытия раздела.

## Ограничения проверки

Браузер не смог подключиться к локальному предпросмотру. Настоящие скриншоты не получены. HTML-сравнение сформировано из реальных EntryComposer и CSS до/после с одинаковыми вымышленными данными. Это статичная вёрстка, не скриншот и не визуально проверенная мобильная сессия.

До подтверждения публикации не проверялись живой Telegram и финансовые данные пользователей. Новые сценарии проверены локально через обработчики и подставной Telegram-транспорт, а не внешними сообщениями.
