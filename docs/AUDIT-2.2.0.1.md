# Проверка Бургета 2.2.0.1

Проверена staging-ветка после 2.2.0.0. Production не изменяется.

## Исправления

| Сценарий | Причина и исправление |
| --- | --- |
| Нажатие на время в мобильном WebView | Нативный input не вызывал picker явно. Обработчик самого поля вызывает showPicker в пользовательском событии; неподдерживаемый API не блокирует стандартное действие. Тип поля определяется уже при первом рендере. |
| Невозможно стереть число дней | Number('') превращал пустое значение в 0. Черновик остаётся строкой, преобразование и диапазон 1–7 проверяются при сохранении. |
| Редактирование лимитов | Преобразование при каждом символе мешало дробной сумме. Строковый черновик, проверка на выходе из поля. |
| Обеденный вопрос повторно приходит после ответа | Cron читал ответы только в минуту вопроса или при активной проверке расходов. Теперь ответы проверяются также перед повторной доставкой. |
| Обед уже записан в приложении | Очередь проверяет актуальную историю и выходные перед отправкой. |
| Устаревший вопрос о планах | Очередь отменяется после закрытия всех планов, отключения напоминания/модуля и смены дня. |
| Один повреждённый профиль останавливает cron | Обработка каждого профиля изолирована; ошибка логируется без финансовых данных. |
| Рабочие дни не выбраны | Вместо молчаливого отказа отображается ошибка. |
| JSON: счёт указан с другим регистром | Предпросмотр выбирает счёт по тем же правилам сравнения имени, что и валидатор. |
| JSON: перевод → расход → перевод | Черновик комиссии сбрасывается вместе с полем операции, чтобы экран не показывал старую комиссию, отсутствующую в данных. |
| Включение напоминаний вместе со сменой пояса | Дата начала учёта отсутствия расходов берётся в новом выбранном поясе. |

## Проверки

139 автоматических тестов: финансовый журнал и отмена операций, переводы и комиссии, курсы, планы и прогнозы, CSV/JSON и дубликаты, сохранение и миграция, авторизация Telegram/веба, изоляция пользователей, приглашения, отчёты, очередь напоминаний и рассылка релизов. Дополнительный детерминированный сценарий выполняет 500 расходов, доходов, переводов и удалений и после каждого шага сверяет сумму остатков до копейки.

Отдельные регрессионные сценарии: пустое число и диапазон 1–7; доступный, отсутствующий и отклонённый showPicker; ответ на обед при выключенной проверке расходов; обед, введённый в Mini App; четыре причины отмены ожидающего вопроса о планах; независимая обработка повреждённого профиля.

## Границы проверки

Автотесты не эмулируют системный Android-пикер внутри Telegram. Открытие системного окна требуется подтвердить на реальном телефоне. Сборка и dry-run не проверяют доставку Telegram при реальном отключении его сети — этот сценарий воспроизводится тестовым отказом API.

Telegram не даёт идемпотентного ключа для sendMessage: если Telegram принял сообщение, а подтверждение не дошло до сервера, при повторе теоретически возможно повторное сообщение. Локальная очередь и подтверждения защищают от обычных повторов; обещать абсолютно однократную доставку нельзя.

Переводы между разными валютами по-прежнему заблокированы: курс не угадывается. Это сохранённое ограничение, а не новый механизм обмена. Аудит не является гарантией отсутствия всех возможных ошибок.
