# Обеды из JSON и упрощение интерфейса · 2.2.0.4

Меню настроек и группы напоминаний получили SVG-значки из существующего набора приложения. Импорт JSON и CSV переключается вкладками: обе большие формы одновременно не отображаются. В ручной карточке операции основные поля — сумма, счёт и категория. Дополнительные поля с описанием, датой, валютой и способом оплаты раскрываются отдельно; при редактировании они открыты. Параметры и значения сохраняются.

В «Обедах» доступны две основные кнопки: «Внести сумму» и «Загрузить JSON». Калькулятор, доплаты, график, формула копилки и расчёт по дням теперь закрыты по умолчанию. Профицит, дефицит, подтверждённая разница и предупреждение о незаполненных рабочих днях остаются видимыми.

## Формат обеда

Используется существующий стандарт `burget-operations` версии 1 с новым типом `lunch`:

```json
{
  "format": "burget-operations",
  "version": 1,
  "operations": [
    {
      "date": "2026-10-14",
      "type": "lunch",
      "amount": 379,
      "currency": "RUB",
      "note": "Суп, горячее, хлеб"
    }
  ]
}
```

Поле `externalId` необязательно; оно допускается только если это настоящий идентификатор исходной записи. `account`, `category`, `paymentMethod`, `from`, `to`, `fee` для обеда запрещены. Сумма — положительное число до двух знаков после запятой. `lunch` означает оплату компанией; личная доплата сохраняется как обычный расход.

Внутри обеденного раздела: файл или вставка → проверка → предпросмотр → подтверждение. До 100 обедов за один импорт, до 2 МБ. Ошибочные строки можно убрать; оставшиеся ошибки блокируют весь импорт. Другие типы операций отправляются в общий импорт. Есть пример и готовый промпт для ChatGPT: из полного меню он требует уточнить выбранные блюда и количества, а не принимать весь прайс за оплаченный заказ.

Поддержка `lunch` также добавлена в общую схему и редактор JSON. Похожие дата/сумма обеда пропускаются по умолчанию, внешний идентификатор не обходится принудительным импортом. Дубли повторно проверяются перед сохранением, включая ранее появившиеся записи и повторения внутри одного файла. Импорт корпоративного обеда не двигает личные остатки при любом режиме изменения банковских остатков.

Проверки: запись без счёта/категории, раздельные бюджеты, дубли файла/истории и внешние ID, будущие даты, валюты, неизвестные поля, атомарность ошибочного пакета; серверный рендер меню с SVG и закрытых дополнительных блоков. Реальный Android WebView отдельно не эмулируется.
