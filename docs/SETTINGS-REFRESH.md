# Сброс настроек при обновлении данных

На исходном коде 2.2.0.1 воспроизведён сброс **несохранённых** настроек «Твой ритм»: изменить поле, получить обновлённый объект settings, увидеть прежнее значение. Mini App запрашивает состояние при возвращении в Telegram и при ручном обновлении. Сохранение другого раздела также заменяет объект settings.

Причина: эффект NotificationSettings при каждой смене ссылки data.settings полностью заменял редактируемую копию. Подтверждённый сценарий не доказывает потерю уже сохранённых настроек при выкладке новой версии. Классический интерфейс хранит данные отдельно; этот патч его не меняет.

Теперь черновик содержит только изменённые поля. Они переживают обновление данных; остальные поля получают актуальные значения. Сохранение применяет только правки поверх текущего состояния, сохраняя изменения других разделов и устройств. Неуспешное сохранение оставляет черновик для повторной попытки. Если пользователь продолжил редактировать во время сохранения, эти новые правки остаются несохранёнными. В форме появился явный индикатор несохранённых изменений.

Регрессионные тесты вызывают настоящие обработчики компонента с изолированным исполнением React hooks: возврат с обновлением данных, сохранение другого модуля, конфликт/отказ сохранения, правка во время запроса и повторное открытие. Первые два теста падали на исходной версии. Это проверка компонента без реального Telegram WebView; мобильная приёмка остаётся отдельной проверкой.

Проверка Worker в обычном CI теперь собирает код через esbuild локально, без обращения к Cloudflare. Это проверяет синтаксис и импорты, но не реальные bindings и настройки Wrangler. Workflow выкладки staging сохраняет отдельную проверку Wrangler перед deployment.
