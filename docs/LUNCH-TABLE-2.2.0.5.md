# Таблица обедов и совместимость JSON · 2.2.0.5

Основой экрана вновь стала таблица из первоначального классического интерфейса. День недели объединён с датой для телефона: дата, доступно, потрачено, ± день, баланс. Итоги месяца занимают одну короткую строку карточек, действия — одну панель. Таблица имеет отдельную прокрутку и закреплённую шапку. JSON, калькулятор и действия дня переключают экран, не растягивая всю страницу.

Доступно = дневной лимит + остаток до текущего дня. Баланс накапливает разницу начисления и записанных обедов только до сегодняшней даты; будущие дни его не увеличивают. Неизвестная сумма отмечена `?`; общий расчёт с такими днями остаётся предварительным. Дневные корректировки и производственный календарь остаются в силе. Расчёт начинается заново для выбранного месяца, без автоматического переноса.

Импорт принимает также документ `burget-lunches-v1` с полями `currency: RUB`, `lunches` и необязательными `employee`, `daily_allowance`. Строки lunches содержат date, amount, необязательные items (name, quantity), note и externalId. Названия/количества составляют описание, дата и сумма переносятся без пересчёта по меню. Метаданные сотрудника и дневного лимита не сохраняются в профиль и не меняют текущие настройки. Неизвестные поля и неверные количества отклоняются.

После преобразования действуют существующие проверки дат, сумм, дублей и явное подтверждение. Операции не записываются на этапе чтения файла. Исходный JSON не изменяется. Допускается один полный Markdown-блок JSON без поясняющего текста; иные обёртки не угадываются. Кнопки скачивания примера и показа промпта разделены промежутком и переносятся на узком экране.

Проверки: совместимость формата, сохранение суммы и описаний, отсутствие смены лимита/профиля/остатков, повторный импорт, неизвестные поля и количества, Markdown, накопительный расчёт таблицы и будущие дни, серверный рендер таблицы и сценария дефицита. Пользовательские персональные файлы в репозиторий не включаются.
